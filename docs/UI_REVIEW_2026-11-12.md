本轮基于 v0.2.23 / `9781469` 的实际浏览器运行界面，完成统一视觉调整、列表显示排序、创建与更新时间及更新限流修复。当前为待主审验收的工作区改动，未提交或发布。

采用紧凑浅色工作台：保留蓝色重点和左导航、任务列表、右侧浮层结构。依据为 `qa/source-reference.png` 与本轮真实运行截图；参考图的说明栏不进入产品。没有引入新 UI 框架、依赖或外部图片。

| 项目标题、任务项目标签重复占用空间 | 项目模式明确分组并省去行内重复项目；其他模式保留项目标识 |

## 显示排序与时间语义

- 所有列表视图共用一个排序入口：手动、项目分组、创建时间、截止日期、完成时间、更新时间。
- 截止日期默认从早到晚，其他时间默认从晚到早，可切换方向。未知、非法及未安排时间始终在最后；同值保留原顺序。
- 时间模式跨项目排序。项目模式按现有项目顺序分组。手动模式严格使用共享任务顺序，只允许同项目及同归档状态内的可见子集重排。
- 显示排序只保存本地界面偏好，不修改 Workspace、任务版本或 MCP 接口。非手动模式隐藏重排手柄，切回手动恢复原顺序。
- `createdAt` 与 `updatedAt` 为兼容可空的带时区时间。真实 GUI/MCP 字段、检查清单、状态、归档、置顶和文件关联变化更新 `updatedAt`，创建时间保持不变。读取、无变化提交、显示排序和任务重排不更新时间。
- 老记录只从明确的受控创建/写入活动恢复缺失字段；不把最早保留活动当成创建。显式 null 保持未知。备份恢复保留历史时间，不写入升级或恢复当天的虚构时间。
- SQLite 在事务边界统一维护时间；GUI 保存接收服务器确认后的快照。文件导入的独立事务、MCP 本地编辑、批量修改及重试路径也覆盖到。正常 compact/full MCP 结果包含时间字段，活动历史仍按需读取。

## 更新限流

自动检查尝试持久保存，间隔 6 小时；手动检查至少间隔 60 秒。原生文件锁覆盖多个窗口及 GUI 进程。真实限流根据 Retry-After、reset/remaining 与受控次级限流响应处理，跨重启保留；重复限流采用有界退避。普通 403 不被误称为限流。

只有完整遍历所有 Releases 页面并验证最高稳定 SemVer 的资源，才能确认结果。部分页面、失败或冷却跳过不构成“当前最新”的证据；没有增加 `/latest`、旧版本回退或 GitHub Token。下载签名验证、渠道隔离和明确安装操作保留。

错误截图只能证明收到限流信息，不能确定某个 IP、代理或点击行为是原因。规则依据：[GitHub REST API rate limits](https://docs.github.com/en/rest/using-the-rest-api/rate-limits-for-the-rest-api)。Tauri updater 2.11.0 的公开流程不提供清单/下载响应头；精确响应头处理覆盖 TodoList 自己的 Releases REST 请求。清单失败保持明确错误并受持久尝试间隔限制，不伪造服务端重试时间。

## 可重复预览

在仓库运行 `npm.cmd run dev -- --host 127.0.0.1 --port 5197 --strictPort`，打开 `http://127.0.0.1:5197/?demo=1`。空白 origin 使用演示数据；需要压力场景时，在该隔离 origin 的设置中导入 `qa/review-2026-11-12/synthetic-browser-fixture.json`。此夹具含浏览器 data URL 图片，只用于浏览器预览，不导入日常桌面库。

便签路径为 `/?demo=1&mode=sticky`。合成限流路径为 `/qa/review-2026-11-12/update-state-preview.html`，它使用真实更新展示组件和固定状态，不调用更新源。验收完停止自己启动的进程。本轮预览已停止，未保留后台服务器。
